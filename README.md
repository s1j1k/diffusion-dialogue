# Diffusion Dialogue

Open-domain dialogue generation with a continuous text diffusion model. The
response is generated by denoising word embeddings, conditioned on the
prompt, rather than token by token.

*Started as a group reproduction of DiffuSeq (Gong et al., 2023) for the AI for
Engineers subject at the University of Melbourne (2024), then rewritten from
scratch, with the bug that wrecked the original results found and fixed.*

## How it works

```
prompt:    [CLS] my cat knocked everything off the desk [SEP]   ← kept clean
response:  noise noise noise noise noise noise noise ...        ← denoised over K steps
                         │
             transformer sees both, predicts clean embeddings x̂0
                         │
response:  [SEP] classic cat behaviour honestly [SEP] [PAD] ...
```

- Tokens are mapped to learned 128-d embeddings. Gaussian noise is added to
  the **response positions only** ("partial noising"), so the prompt
  conditions generation through ordinary self-attention, with no separate
  encoder or classifier.
- A transformer is trained to predict the clean response embeddings `x0`
  from the noisy ones at a random noise level.
- Generation starts from pure noise and repeatedly applies the model with a
  deterministic DDIM-style update, snapping each estimate to the nearest
  word embedding. The number of steps is a dial between speed and quality.

## The bug that broke the original model

The 2024 version scored a BLEU of 0.0005 and produced random words. The
cause was not the small dataset: **training treated the network's output as
the clean data, while sampling treated it as the noise**. With a perfect
denoiser plugged in, the original sampler still reconstructs 0 % of tokens;
fixing that one interpretation gives 100 %. The rewrite uses a single
parameterisation throughout, and a unit test runs the perfect-denoiser check
so the bug cannot return. Full analysis, with six smaller defects:
[docs/TECHNICAL_NOTES.md](docs/TECHNICAL_NOTES.md).

## Status

Current model **v0.1** (7.5M parameters, trained for ~1 hour on a laptop
CPU) learns to denoise but still produces word soup; compare versions in
[benchmarks/](benchmarks/README.md). A GPU run is next: matching DiffuSeq's
training budget would take decades on this CPU (see the research log).

## Usage

```sh
pip install -r requirements.txt
pytest                                   # ~1 min on CPU

# Data: DiffuSeq's Commonsense Conversation release (3.4M pairs, ~730 MB)
gdown --folder https://drive.google.com/drive/folders/1exENF9Qc5UtXnHlNl9fvaxP3zyyH32qp \
      -O datasets/CommonsenseConversation

# Train (GPU), or a small model on CPU
python scripts/train.py --out runs/base
python scripts/train.py --preset cpu-small --train-limit 200000 --out runs/cpu-small

# Generate and score responses for 1,000 test prompts with 200 sampling steps
python scripts/evaluate.py --ckpt runs/base/checkpoint.pt --steps 200

# Chat with a checkpoint through a local inference server
python scripts/serve.py --ckpt runs/base/checkpoint.pt
curl -s localhost:8000/generate -H "Content-Type: application/json" -d '{"prompt": "what are you doing this weekend?"}'
```

`datasets/sample/` has a few pairs for a quick smoke test
(`--data datasets/sample`).
